# Packaging

Prebuilt packages are produced with `scripts/build.sh` (conda env → conda-pack → OS-specific archive). The same script is used locally and in GitHub Actions.

conda-pack environments are single-architecture. Each package is built on a runner of the target OS and CPU.

## Artifacts

| Platform | Runner | File |
|---|---|---|
| macOS Apple Silicon | `macos-15` | `FlatCAM-<version>-macos-arm64.dmg` |
| macOS Intel | `macos-15-intel` | `FlatCAM-<version>-macos-x86_64.dmg` |
| Linux x86_64 | `ubuntu-24.04` | `FlatCAM-<version>-linux-x86_64.tar.gz` |
| Windows x86_64 | `windows-2022` | `FlatCAM-<version>-windows-x86_64.zip` |

macOS: open the DMG and drag `FlatCAM.app` to Applications. Start from Terminal with `./FlatCAM.app/Contents/MacOS/FlatCAM` if Finder shows no error.

Linux: extract the archive and run `./FlatCAM/FlatCAM`.

Windows: extract the zip and run `FlatCAM.bat`.

## Local build

From the repository root, on the OS you want to package:

```bash
./scripts/build.sh
```

Force a target (must match the host):

```bash
./scripts/build.sh macos
./scripts/build.sh linux
./scripts/build.sh windows
```

`./scripts/build-dmg.sh` is a wrapper for `./scripts/build.sh macos`.

A full rebuild starts with `rm -rf build`.

### Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `APP_VERSION` | git tag, or `dev` | Version in the artifact file name and `Info.plist` |
| `APP_NAME` | `FlatCAM` | Bundle / folder name |
| `MAMBA` | `build/bin/micromamba` | Existing micromamba/mamba |
| `ENV_PREFIX` | `build/env` | Conda environment prefix |
| `SKIP_ENV_CREATE=1` | unset | Reuse `ENV_PREFIX` or an activated env (used in CI) |
| `BUILD_DIR` | `<repo>/build` | Working directory |

Optional patches in `packaging/patches/*.patch` are applied with `patch -p1` before the env is created.

### macOS extras

Optional prettier DMG layout locally: `brew install create-dmg`. CI and machines without it use `hdiutil` and an Applications symlink.

Apple signing and notarization are not part of this pipeline.

## GitHub Actions

Workflow: `.github/workflows/build.yml`.

- Manual run: **Actions → Build → Run workflow**
- Git tag (`1.9.0` or `v1.9.0`): builds all four targets and attaches the files to a GitHub Release

Adding another OS later: add a `packaging/<os>/` launcher, a `package_<os>` function in `scripts/build.sh`, and a matrix row in the workflow. The env create + conda-pack steps stay shared.

## Layout

```text
packaging/
  macos/     Info.plist, launcher.sh
  linux/     launcher.sh
  windows/   launcher.bat
  patches/   optional extra .patch files
scripts/
  build.sh
```
